# 研究简报：无监督聚类式去敏 + 压缩插件（PrivTrim-IoT 主线 v1）

> 日期：2026-10-15 ｜ 状态：方案设计（未开始实现）
> 依据：yf-research（先射箭再画靶 / 跨领域迁移是正式创新路径 / 消融定主线）+ yf-skill（贡献与价值成为阅读主线）

---

## 0. 一句话

**把 PACT（CVPR 2025）的"距离有界聚类"从效率工具改造成"隐私约束下的语义泛化器"，做成一个免训练插件放进现有冻结 harness 的第 12 条 track——它同时压缩和去敏，并且覆盖正则结构上够不到的改述内容。**

---

## 1. 靶子：已经量化出来的缺口

动机实验（`paraphrase_probe/`，24 案例 / 72 标识符 / 600 变体样本，**0 次模型调用**），口径完全复刻项目现有 `redact()` / `exposure()`：

| 类别 | 数量 | 占比 |
|---|---:|---:|
| 检查器看见 + 正则删掉（安全） | 120 | **20.0%** |
| 检查器看见但正则删不掉（会计入泄漏） | 240 | **40.0%** |
| **检查器看不见（对指标隐形）** | 240 | **40.0%** |

**按标识符类型的正则删除率（完整值）**

| 类型 | 原始格式 | 变体 | 落差 |
|---|---:|---:|---:|
| email | 24/24 = 100% | 48/192 = **25.0%** | 75.0 pp |
| phone | 24/24 = 100% | **0/168 = 0%** | 100 pp |
| account | 24/24 = 100% | **0/168 = 0%** | 100 pp |
| **合计** | **72/72 = 100%** | **48/528 = 9.1%** | **90.9 pp** |

**可复现的个例**（每项 24 个案例全部如此）：`+1 202 555 0100`、`+1.202.555.0100`、`+1 (202) 555-0100`、`12025550100`、`acct-fe9d1258b732`、`ACCT fe9d1258b732` —— 正则一律漏掉。

**这个数字给三件事**：
1. 现有 `mask_*` 的 1.000 移除率是**格式特定**的，不是隐私保证（正是导师说的"benchmark result, not a general guarantee"）。
2. **40% 的样本连"泄漏"都报不出来**——`exposure()` 匹配失败时该条既不进泄漏计数也不进移除计数，等于对指标隐形。这是测量有效性问题，必须先修。
3. 这个缺口**恰好是导师点名要求覆盖的 paraphrase 场景**，不需要另找理由。

## 2. 暂定问题（射箭）

> 在**固定本地模型、同一 token 预算、同一隐私前端位置**下，一个免训练、无监督的聚类插件能否同时做到：
> (a) 压缩到与现有压缩器同一预算档，效用不显著下降；
> (b) 把去敏覆盖从"可模式匹配的标识符"扩展到**语义等价的敏感内容**，并把隐形泄漏变成**可测量**的泄漏？

靶子已经量化（第 1 节），所以这是一个**可证伪**的问题。

---

## 3. 继承 vs 差异（写论文时必须说清的部分）

| 来源 | 继承什么 | 我们改什么 |
|---|---|---|
| **PACT**（arXiv 2504.08966, CVPR 2025） | 早层**重要性度量**（不依赖 attention，FlashAttention 兼容）；**Distance Bounded Density Peak Clustering** 把簇内距离约束在阈值内 | 把"距离"从**单一冗余度量**拆成**双度量**；把合并结果的去向从"丢给 LM"改成"**簇原型替换**" |
| 本项目 `mask_*` 前端 | 位置（放在压缩之前）、同预算协议、审计回执 | 从**删除**改为一词：**泛化**（正则只能抹除，聚类可以给类别标签） |
| 本项目现有 harness | 11 条 track、matched/native 双预算轨道、逐例评分、Holm 校正、`frozen_sources`、审计回执 | 新增第 12 条 track，其余全部不动 |
| 用户自己的 3D VLM 压缩 harness | `visionzip` / `vispruner` / `sparsevlm` / `published_selection` 的 b0p125/b0p25 × closed/open 接口 | 选择器接口直接搬过来 |

**差异的实质（去掉方法名也能说清）**：PACT 用"看起来像不像"决定合并谁；我们额外用"**合起来会不会把两个不同敏感取值混成一类**"来禁止某些合并。前者管效率，后者管隐私。**这是组件间的新约束关系，不是 A+B+C 堆叠。**

## 4. 机制设计

```
输入日志/上下文
   │
   ├─(1) 早层 hidden states ──► 两个度量
   │        d_red  : 冗余距离（PACT 原样）      → 决定"可以合并谁"
   │        d_sens : 敏感距离（敏感子空间上的距离）→ 决定"禁止合并谁"
   │
   ├─(2) 距离有界聚类（DBDPC 或 agglomerative）
   │        约束：簇内 d_red ≤ τ_red  且  簇内 d_sens ≤ τ_sens
   │
   ├─(3) 簇原型替换（不是删除）
   │        敏感簇 → 类别标签 / 泛化描述
   │        冗余簇 → 单个代表 token（压缩收益）
   │
   └─(4) 输出：压缩后的上下文 ──► 固定本地模型
```

**三个设计点各自对应一个可测收益**：

| 设计点 | 预期收益 | 对应消融 |
|---|---|---|
| `d_sens` 约束 | 阻止不同敏感取值被混为一类（假合并） | 去掉 `d_sens` |
| 簇原型替换 | 保留语义、避免正则的"抹除"式信息损失 | 换成 `[REDACTED]` |
| `d_red` 合并 | token 减少（PACT 原生） | 换成随机合并（同预算） |

---

## 5. 两条并列的收益（都要写，不二选一）

1. **隐私覆盖**：变体上的完整值删除率，从 **9.1%** 起步往上提；并把**隐形泄漏（40%）转成可测量**。
2. **压缩效率**：在同预算下与 QUITO-X / CPC 可比，且**不需要训练**（省掉训练成本和归因混杂）。

---

## 6. 缝合后的实验设计

所有 arm 共用：同一个隐私前端位置、同一个 token 预算、同一套评分。

| Arm | 内容 | 作用 |
|---|---|---|
| A0 | `full`，不过滤不压缩 | 效用上界 / 隐私下界 |
| A1 | **filtered full context**（只过滤不压缩） | 隔离"过滤代价"（导师明确要求新增） |
| A2 | `mask_quito_x`（现最强） | 强简单基线，**必须打赢的对象** |
| A3 | 聚类插件，只用 `d_red` | 消融：聚类本身够不够 |
| A4 | 聚类插件，`d_red` + `d_sens`，**泛化替换** | **主方法** |
| A5 | 聚类插件，`d_red` + `d_sens`，删除替换 | 消融：泛化 vs 抹除 |
| A6 | **随机合并**，同预算 | 消融：聚类 vs 随机（闭包悲剧的防重演） |

预算档：25% / 50% / 75% × matched/native 双轨（沿用现有协议）。

**指标分开报，各带分母**（导师硬要求）：
- 去敏：完整值移除率、片段移除率、**paraphrase 检出率**、隐形泄漏率
- 输出泄漏：完整输出检查，**含改述**
- 任务：EM / F1
- 成本：**过滤 + 聚类 + 压缩总延迟**（导师明确要求计入）

> ⚠️ **`joint_fragment = 2·F1·P/(F1+P)` 是调和平均，先拆掉再跑**，否则新方法也会被同一个坏指标糊住。

---

## 7. 主线由消融决定 + 停止规则

**主线候选**（跑完 A3–A6 后按证据选）：
- 若 A4 > A3 → `d_sens` 是核心，主线 = "隐私约束下的聚类"
- 若 A4 ≈ A3 但 A4 > A6 → 核心是"聚类"本身，主线 = "聚类式泛化"
- 若 A4 ≈ A6 → **聚类不是机制**，老实报负结果，主线退回"paraphrase 感知的测量协议"（第 1 节那 40% 本身就是可发表的发现）

**停止规则**（yf-research 的四次规则）：同一方向完成 4 次有效抽样实验、效果都明显差 → 保留全部结果，转向消融中表现好的候选。**轻微不足先查样本代表性、预算与实现，不当作"效果很差"。**

## 9. 与导师清单的逐条对齐

| 导师要求 | 本方案如何满足 |
|---|---|
| "focus on a precise question" | 第 2 节的暂定问题，靶子已量化 |
| "document what makes events linked / how selected within budget / conflict handling" | 第 4 节的 `d_sens` 约束就是"冲突时隐私优先"的可执行版本 |
| "privacy rules must take priority" | 簇内不得跨越不同敏感取值 = 硬约束 |
| "check complete input and output incl. paraphrases" | V1 直接做这件事，且已有 40% 的量化动机 |
| "95% is a benchmark result, not a guarantee" | 第 1 节证明现有 100% 是格式特定的 |
| "report removal, output leaks and accuracy separately with denominators, no harmonic mean" | 第 6 节四类指标分离 + 拆掉 `joint_fragment` |
| "keep same-filter matched-budget control and event-link ablation" | A2 + A3/A4 |
| "add filtered full context as a reference" | A1 |
| "measure filtering/compression time in total latency" | 第 6 节成本行 |
| "freeze policies, labels, cases and code before final runs" | 沿用现有 `frozen_sources` + 预登记机制 |
| "extend related work to privacy-aware IoT filtering and prompt compression" | V5 |
