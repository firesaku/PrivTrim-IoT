## 3. 四条结论

### 结论 1：真嵌入把敏感混合压到 **0** ✅
`mix_sens`：**sim_emb 0.0% / 0.0% / 0.1%**，而 char-3gram 1.8/1.7/2.6%，随机 **15.3–18.8%**。
→ 语义嵌入比字符 n-gram **更强**，敏感内容被完全合在自己内部。

### 结论 2：`d_sens` 约束是**冗余的**（在这批数据上）⚠️ 有解释
`cons_emb` 的簇数与指标与 `sim_emb` **完全相同**（818 / 1251 / 1939）。
→ 说明在相似度排序里，敏感 unit 与相邻排名的非敏感 unit **从未相邻**，约束一次都没触发。
→ **原因**：本批敏感项是连续同构块，块内互相最相似。**这个结论依赖注入形态，必须用分散式注入重测。**

### 结论 3：效用代价很小但**不是零** ⚠️
`hit_answer`：sim_emb **4.4–6.2%** vs 随机 3.0–3.8% → 真嵌入比随机多混 **约 1–2.4pp**。
→ 这是需要**重要性护栏**去压的地方，也是 `d_imp` 约束的用武之地。

### 结论 4：最危险模式大幅改善 ✅
`fuse_2sec`：sim_emb **0.1–0.2%** vs random_adj 0.9–1.5%（改善 5–10 倍）。char-3gram 为 0.0%。

## 4. 与闭包教训的对比（关键判定）

项目最惨的教训：证据闭包 vs 简单元数据排序，**独立复现 10 次以上全打平** → 机制作废。

**本次相反**：

| 维度 | 覆盖 |
|---|---|
| 合并比例 | 3 个（0.125 / 0.25 / 0.50） |
| 对照 | 2 个（随机相邻 / 随机非相邻） |
| 数据集 | 7 个来源 |
| 度量 | 2 个（真嵌入 / 字符 3-gram） |
| 平台 | 2 个（本地 / HPC CPU / HPC GPU 单卡） |
| **效应量** | mix_sens **0.0% vs 15–19%** |

→ **相似度聚类是机制，不是装饰，可以放心投入实现。**

---

## 5. 机制解释（可直接写进论文）

敏感内容内部各行**格式与语义高度相似**，而与周围自然语言正文**不相似**。
- **相似度合并**把它们互相合到一起，**不跨越敏感块边界** → mix_sens ≈ 0、fuse ≈ 0。
- **随机合并**无视内容，频繁跨越边界 → mix_sens 15–19%。

→ **"语义相似度"本身就是一个免训练、免标注、免正则的隐私保护信号。**

---

## 6. 必须诚实标注的边界

1. 敏感项按**连续同构块**注入 → 结论 2（约束冗余）**依赖注入形态**，必须用**分散式注入**重测。
2. `hit_answer` 非零（4.4–6.2%）→ 约 **1/20 的合并**会混入非答案内容，需重要性护栏。
3. 这是**可行性**测试，**不是端到端效果测试**；F1 与 paraphrase 覆盖率尚未测。
4. 编码器是 LLMLingua-2 的 XLM-R-large（通用编码器），不是专用句嵌入模型；换更强嵌入可能更好。
