## 2. 机制挖掘：哪些操作能**同时**去敏 + 提性能

从你的 11 条 track 里把"操作"抽出来，而不是看方法名：

| 操作 | 压缩 | 去敏 | 提升性能 | 证据（HPC 全量，pooled mean） |
|---|:--:|:--:|:--:|---|
| **删除任务无关内容** | ✅ | ✅ | **✅** | `mask_*`：ΔF1 26/32 为正，Δjoint 32/32 为正，最大 **+17.30pp** F1；`mask_quito_x` F1 55.72 且移除率 100% |
| **抽象 / 改写** | ✅ | ✅ | ⚠️ 中性 | `cpc` 在无 mask 情况下移除率已达 **97.81%**，F1 50.35 —— 重写让表面形式不存活 |
| **细粒度单元** | ✅ | ✅ | ✅ | token 级（`quito_x`/`dac`）比句子级（`provence` 66.00%）移除率更高 |
| **抽取 / 选择** | ✅ | ❌ | ✅ | `quito_x` F1 51.87 但移除率仅 **34.84%** —— 原样 token 存活 |
| **粗粒度（句子级）** | ✅ | ⚠️ 弱 | ✅ | `provence` 移除率 66.00%，F1 51.45 |
| **去噪（删干扰项）** | ✅ | 顺带 | **✅** | Qwen/HotpotQA：`mask_quito_x` 53.97 **>** `full` 53.54 —— 删 token 反而涨分 |
| **破坏式删除** | ✅ | ✅ | ❌ | `dac` 移除率 90.87% 但 F1 仅 **27.32** |
| **不裁剪输出** | ⚠️ | — | **✅** | batch1：`provence` 68.49→81.08、`cpc` 76.36→82.48（native 无末尾截断） |

### 四个可直接复用的"双赢"机制

1. **删任务无关项（denoising）** —— 已被 `mask_*` 证实：既去敏又涨分。**根因**：任务无关的标识符是纯干扰。
2. **抽象优于抽取（abstraction）** —— `cpc` 的干净度不是设计出来的，是"重写"这个操作的副产品。**你做聚类原型替换，天然继承这个性质。**
3. **细粒度优于粗粒度（granularity）** —— 单元越小，敏感跨度的存活率越低。
4. **别裁剪，让输出比预算短（native）** —— 对句子/抽象类方法是 10pp 级别的差异。

### 两个反模式（别踩）

- **纯抽取式无法去敏**：原样保留 token = 原样保留标识符。
- **靠破坏换隐私**：`dac` 是这条路的下场（隐私 90.87% / F1 27.32），没有意义。

## 3. 核心设计原则：**敏感度 × 任务相关性 四象限路由**

把上面四个机制拼起来的那把钥匙，是一个 2×2：

|  | **任务无关** | **任务相关** |
|---|---|---|
| **敏感** | **删除** ← 现有 mask 已证明双赢 | **泛化 / 原型替换** ← 导师点名的冲突场景，**现在零覆盖** |
| **不敏感** | **合并**（压缩） ← PACT 的活 | **保留** ← 效用关键，绝不能动 |

**这张表就是你的路由器，也是你一句话能说清的贡献。** 它同时做到了三件事：
- 用上了"删除"这个已验证的双赢机制（左下→左上）
- 用上了 PACT 的聚类（左下格）
- 填上了导师明确指出的空位（右上格）

**右上格是唯一没人做过、也没有天花板封顶的地方。** 其余三格都是"把已知的事做对"。

## 4. 五个组合方案

### 组合 1：串联（Rule → Cluster）
```
正则脱敏 ──► 聚类压缩 ──► 模型
```
- **依据**：现有数据已证明 mask 在前、压缩在后有效（32/32）
- **预期**：与 `mask_quito_x` 同水平，最多略好
- **局限**：覆盖不超出正则（paraphrase 仍是 9.1%）
- **失败说明**：聚类在这个位置没有附加值 → 退回组合 2

### 组合 2：双通道路由（抽取 ⊕ 泛化）★ 主推
```
         ┌─ 通道 A（保效用）：抽取式选择，保留答案相关 token ──┐
输入 ────┤                                                      ├──► 合并 ──► 模型
         └─ 通道 B（保隐私）：聚类 + 原型替换，处理敏感跨度 ────┘
                        路由：第 3 节的四象限
```
- **依据**：`quito_x` 的高 F1（51.87）+ `cpc` 的高移除率（97.81%）**是两个不同操作带来的**，现有方法都只能用其中一个
- **预期**：F1 接近抽取式，移除率接近抽象式，**且覆盖到 paraphrase**
- **优点**：两条收益都写得出（yf-skill 的"并列保留"）
- **失败说明**：若合并后 F1 明显掉 → 两个通道的粒度不兼容（需对齐到同一 unit）

### 组合 3：簇内路由（单次聚类，簇级决策）
```
聚类 ──► 每个簇按 敏感度×相关性 选一种操作 {合并 | 原型替换 | 保留}
```
- **依据**：PACT 的 Distance Bounded Density Peak Clustering + 你的 `d_sens` 约束
- **优点**：工程最小、叙事最干净（"一个聚类，一次决策"）
- **失败说明**：若簇内混合了敏感与相关 token，簇级决策会二选一都错 → 需要簇内再切分

### 组合 4：级联预算重分配
```
去敏（省下 token）──► 预算还给任务相关证据 ──► 压缩
```
- **依据**：`mask_*` 证明删除无关键**不会**掉分（26/32 反而涨），省下的预算可以回收
- **预期**：同预算下效用持平或上升，覆盖率提高
- **失败说明**：若预算回收没带来增益 → 说明瓶颈不在预算而在选择质量

### 组合 5：原型注入（prototype-as-context）
```
ACCT-fe9d1258b732 ──► [账户类别A]      （而不是 [REDACTED]）
```
- **依据**：`cpc` 的干净度来自"重写"；原型是轻量重写，保留了"这里有一类东西"的可推理信息
- **预期**：对含敏感项的推理题，比 `[REDACTED]` 空洞保留更多可用信息
- **失败说明**：若原型与 `[REDACTED]` 无差异 → 模型不需要那层语义，退回删除即可

## 5. 组合的正交轴（避免组合爆炸）

| 轴 | 选项 | 由哪个结果支持 |
|---|---|---|
| 去敏操作 | 删除 / 泛化(原型) / 改写 | mask 双赢；cpc 干净；原型待验证 |
| 压缩操作 | 抽取 / 合并(聚类) / 改写 | quito_x 高 F1；PACT；cpc |
| 顺序 | 去敏→压缩 / 同时 | mask 在前已验证 |
| 粒度 | token / 短语 / 句子 | 细粒度移除率更高 |
| 决策依据 | 规则 / 重要性 / 距离 / 敏感度 | 全部已有实例 |

**建议只做 2×2，不要全因子**：`{抽取, 聚类}` × `{删除, 泛化}` = 4 个 arm，再加 `mask_quito_x` 基线和随机合并对照。

## 6. 最小可跑组合（建议起点）

**先做组合 3 + 组合 5 的并集**，因为它同时最简、最新、最省工程：

```
聚类（d_red 有界 + d_sens 有界）
  └─ 簇级路由：
       敏感簇        → 原型替换（泛化）
       冗余非敏感簇  → 合并为代表 token
       任务相关簇    → 原样保留
```

**对照**：`mask_quito_x`（现状基线）、随机合并（同预算）、纯 `d_red`（去掉隐私约束）。

---

## 7. 必须预登记的消融（防重演闭包悲剧）

| 消融 | 去掉什么 | 若结果说明什么 |
|---|---|---|
| 去 `d_sens` | 隐私约束 | `d_sens` 是核心（→ 主线 = 隐私约束下的聚类） |
| 去聚类，改随机合并 | 聚类本身 | 聚类不是机制（→ 主线退回测量协议） |
| 泛化 → 删除 | 原型替换 | 泛化无附加值（→ 主线 = 聚类合并 + 删除） |
| 去 paraphrase 测试集 | 新覆盖 | 新方法只等于现有 mask（→ 无创新，收窄为测量论文） |

## 8. 与现有证据的一致性检查

| 主张 | 是否与已有数据冲突 |
|---|---|
| 聚类能同时压缩和去敏 | 不冲突；`cpc` 已证明抽象类操作天然干净 |
| 泛化优于删除 | **待验证**（无现有数据，属新假设） |
| 细粒度更利于隐私 | 一致（`quito_x` vs `provence`） |
| 删无关键能涨分 | 一致（26/32、HotpotQA 反超 full），**但仅限"任务无关" regime** |
| 抽取式单独不能去敏 | 一致（`quito_x` 移除率 34.84%） |

> ⚠️ 一处必须诚实：**"删除能涨分"只在"敏感且任务无关"时成立。** 一旦敏感项与任务相关（导师点名的冲突场景），删除必然掉分——**这正是右上格需要"泛化"而不是"删除"的原因。**
