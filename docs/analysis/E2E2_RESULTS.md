## 3. 差距在哪：**不是聚类，是选择器**

关键数字：**`mask_quito_x` 在 50% 预算下保住了 full context 的 98.2%**
（SQuAD：87.94 / 89.53 = **98.2%**；HotpotQA：56.62 / 55.30 = **102.4%，甚至反超**）

而我的最好臂只保住 **67.7%**（SQuAD 60.63 / 89.53）和 **74.1%**（HotpotQA 41.00 / 55.30）。

→ **SQuAD 任务几乎不需要另外那 50% 的 token；QUITO-X 的 token 级打分（flan-T5 + query）极其精准地留住了答案 token。**
→ 我的"嵌入相关性排序"是**弱得多的选择器**，会整句/整窗丢掉答案。

**所以：机制（聚类）没问题，选择器差得远。**

---

## 4. 因此下一步非常明确

**把聚类叠加到 QUITO-X 上** —— 即 `mask_quito_x + clustering`，而不是继续改我自己的选择器。

- 现有 `+7.4 / +8.0 pp` 的聚类增益是在**弱选择器**上测得的；
- 如果这个增益能迁移到 **QUITO-X 这种强选择器**上，就直接超过基线；
- 而且这完全复用他们已经跑通的 QUITO-X 代码与预算逻辑（`run/` 里就有）。

同时：
- 我之前提的"把聚类下移到 token 级"**已经做了**，结论是 token 级增益更小（+3.0~3.9pp）且绝对分数更低（重建碎片化伤流畅度）→ **句子级更好，粒度不是瓶颈**。
