# 09 · 长上下文实验结果分析（yf-skill 框架）

> 2026-10-17 ｜ 112 例确定性长上下文基准，Qwen2.5-7B-Instruct，官方 SQuAD 评分
> **主结果：作业 10602067，`maxlen=24576`，112 例零截断**（真实 tokenizer 实测：8192 下 47 例超长、7 例金答案被砍掉）
> 全部 18 个预算格 `ov = 0`（逐例预算对齐，超标直接 raise）

---

## 1. 主线（一段话）

**长上下文 IoT 日志的压缩此前无法被严肃评估**：项目唯一能打分的数据是 SQuAD（135 词）与 HotpotQA（910 词），在上面压缩一半只掉 0.75 分 —— 因为短文里本来就没有可压缩的东西。本文构建了第一个**答案由数据源自身结构化记录确定性导出**的长上下文基准（112 例，842–4880 词），并在其上得到两个结论：

1. **压到约 46% 的 token，F1 与不压缩持平**（0.7182 vs 0.7189）。
2. **同预算下，"保护问题所指实体"这一条规则把 F1 从 0.4688 提到 0.7182（+0.249）**。

机制清楚且由中间量直接支持：日志里 k 条几乎同形的实体记录块是全文**最冗余**的单元，纯冗余度选择器**第一个丢它们** —— 机密保住了、上下文缩短了、而问题变得无法回答（目标实体存活率 0.643 vs 1.000）。常用的"答案是否还在上下文里"指标对这个失败**完全失明**：两个臂都报 100%。

## 3. 核心贡献与对应证据

### 贡献 A｜实体锚点保护：同预算 +0.249

`budget_cluster`（0.4688）→ `budget_cluster_link`（0.7182），**ratio=0.50，token 数 3705 vs 3706**。同选择器、同预算，只差"是否保护问题所指实体"这一条规则。

中间量直接给出机制：

| 臂 @0.50 | F1 | 目标实体存活 | `ans_in_ctx` |
|---|---:|---:|---:|
| `budget_cluster` | 0.4688 | **0.643** | **1.000** |
| `budget_cluster_link` | **0.7182** | **1.000** | 1.000 |

**观测**是"实体存活 0.643 vs 1.000，F1 0.4688 vs 0.7182，预算相同"；**解释**是"同形实体块被冗余度排序排在丢弃序最前"。后者由 `tent` 这一中间量支持，不是事后归因。

### 贡献 B｜质量与效率并列

| 臂 | F1 | ctx tokens | 相对 `full` |
|---|---:|---:|---|
| `full` | 0.7189 | 7964 | 100% |
| **`budget_cluster_link` @0.50** | **0.7182** | **3706** | **46.5%** |
| `budget_cluster_link` @0.75 | 0.7191 | 5581 | 70.1% |

**压到 46.5% 的长度，F1 差 −0.0007（在噪声内持平）。** 效率收益明确，质量不受损。

值得注意的方向性观察：在**公平子集**上该臂此前略高于 `full`（0.7299 vs 0.7002），全量无截断后变为持平。机制解释仍然一致 —— 删冗余单元同时删掉了干扰项；全量下这一效应被更多需要长上下文的案例摊薄。**如实报持平，不把子集上的 +0.03 当作普遍结论。**

### 贡献 C｜压缩率的工作区间很宽

`budget_cluster_link`：25% → 0.6545，50% → **0.7182**，75% → 0.7191。**50% 与 75% 几乎相同**，说明该方法在 50–75% 之间存在一个**平坦的工作区间**，而不是需要精调的尖峰。25% 才明显下滑（切掉了推理所需上下文）。

这比"存在唯一最优点"更有用：**工程上不需要精确调参，取 50% 即可。**

### 贡献 D｜测量贡献：标准保留率指标对"链接摧毁"结构性失明

多实体子集上 `ans_in_ctx` 是 **1.000 vs 1.000**，而目标实体存活是 0.643 vs 1.000、F1 是 0.4688 vs 0.7182。

**该指标测的是"字符串在不在"，任务要的是"实体→属性的链接通不通"。** 这解释了**为什么这类失败此前一直没被发现** —— 用标准保留率做质检，会把一个大幅掉分的上下文判为完美。

### 贡献 E｜删除与稳定别名：同效用，身份保全差异是二元的

| 臂 | F1 | collision | gold_in_ctx |
|---|---:|---:|---:|
| `delete` | 0.4916 | **40** | 0.982 |
| `alias` | 0.4933 | **0** | 1.000 |

**效用打平（+0.0017），但 `delete` 在 40 个多实体案例上 100% 摧毁实体身份，`alias` 是 0。** 且在预算臂内同样成立：`delete_budget` 0.4688 / collision 40，`alias_budget` 0.4866 / collision 0 —— **别名在预算压缩下还略高，且不摧毁身份。**

`delete` 另有 2/112 例把金答案直接删掉：那 2 个答案是**源数据里的真实邮箱地址**，不是注入的哨兵。

## 4. 主动发掘的优势场景

| 场景 | 观察 | 为什么优势最大 |
|---|---|---|
| **多实体消歧** | 同预算 +0.249 | 有 k 个同形实体块可被误丢；单实体案例无此风险 |
| **长日志 + 冗余填充**（842–4880 词） | 46.5% token 持平 | 冗余度信号在高冗余文本上信息量最大；短上下文里接近噪声 |
| **需区分"是哪一个"的查询** | `ans_in_ctx` 满分而 F1 掉 0.25 | 只有需要链接的查询会暴露；纯抽取式查询不受影响 |

**共同点：都需要在多个同形对象之间保持区分度。** 这是删除式脱敏的失效边界，也是本方法的适用面。

## 5. 三种贡献层级

| 层级 | 对应物 | 独立验证 |
|---|---|---|
| **数据 / 评测协议** | 112 例确定性基准 + 同预算对照 | 产物 sha256 `7d375880…`；`PYTHONHASHSEED` 四值字节级相同；18 个预算格 `ov=0` |
| **基础骨架** | 冗余度选择器 | 显著优于同预算随机臂：0.4688 vs 0.2277 |
| **附加组件** | 实体锚点保护 | 在骨架上加一条规则，同预算 +0.249 |

不把骨架称为标准 baseline；`budget_random` 才是本文对照臂，且预算逐例相等。

## 6. 协议强度

| 项 | 做法 |
|---|---|
| 预算对齐 | 逐例 `B = round(ratio × nt(full_context))`，tokenizer 实测；**18/18 格 `ov=0`** |
| 硬失败 | `check_budget` 超标直接 raise；`--maxlen-policy raise`：提示词超长报错，不静默截断 |
| 长度 | `maxlen=24576`，112 例零截断（8192 下 47 例超长、7 例金答案被砍） |
| 评分 | 官方 `evaluate-v2.0.py`，多 gold 取 max |
| 解码 | greedy，`max_new=64`；`make_prompt`/`split_units`/`drop_to_budget` 与既有 harness 源码逐字节同构 |
| 隐私 | 判定逻辑单一来源 `privcheck`；`out_leak_value` 全 0 |
| 金答案 | 由源自身结构化记录导出，**无模型参与生成** |

## 7. 适用边界（集中说明）

- 单 seed / 单模型（Qwen2.5-7B）/ 单卡 V100，**未做方差估计**；±0.001 量级的差异不应解读为显著性。
- 来源 5 个真实数据集（toolmem / SimuHome / PEC-Home / PrivacyLens / SmartBench）；AgentDojo 本机无数据，未纳入。
- 选择器为 `sel=lex`（词面 Jaccard），非嵌入相似度；嵌入版需更大显存。
- 多实体子集 n=25（受该子集长度限制），按源分组的结论样本量更小。

## 8. 不确定度（多种子 + 案例 bootstrap）

### 8.1 种子实验的结论：种子方差不是本文需要的方差

跑了三个种子（20261015 / 20261016 / 20261017）：

| 臂 | 三个种子的 F1 | 均值 ± sd |
|---|---|---:|
| `full` / `delete` / `alias` | 三值完全相同 | **± 0.0000** |
| `budget_cluster` @0.50 / `budget_cluster_link` @0.50 / `delete_budget` @0.50 / `alias_budget` @0.50 | 三值完全相同 | **± 0.0000** |
| **`budget_random` @0.25** | 0.1250 / 0.1071 / 0.1518 | 0.1280 **± 0.0225** |
| **`budget_random` @0.50** | 0.2277 / 0.2507 / 0.3107 | 0.2630 **± 0.0429** |
| **`budget_random` @0.75** | 0.4602 / 0.3976 / 0.5414 | 0.4664 **± 0.0721** |

**只有 `budget_random` 消耗随机数**，其余臂都是给定案例集后的确定性函数，因此 sd 恰好为 0。
这带来两个结论：

1. **本文方法完全可复现**：三个种子给出逐位相同的数字。
2. **种子方差**不能用来给主结论做区间估计 —— 它只说明随机对照有多抖。**正确的不确定度来自案例层面的抽样**，因为不确定性在"抽到了哪 112 个案例"，不在随机数。

随机对照本身抖得很厉害（@0.75 从 0.3976 到 0.5414，极差 0.144）。**即便取它最幸运的那个种子（@0.50 = 0.3107、@0.75 = 0.5414），仍远低于本文方法的 0.4688 / 0.7191。**

### 8.2 案例 bootstrap（4000 次重采样，`r3_percase.jsonl` 的 112 例）

| 对比 | 均值 | 95% CI | 判定 |
|---|---:|---|---|
| **锚点增益 @0.25** | **+0.2443** | [+0.1607, +0.3312] | 不含 0 |
| **锚点增益 @0.50** | **+0.2491** | [+0.1722, +0.3311] | 不含 0 |
| **锚点增益 @0.75** | **+0.2241** | [+0.1429, +0.3125] | 不含 0 |
| 聚类 − 随机 @0.50 | +0.2414 | [+0.1429, +0.3482] | 不含 0 |
| **锚点臂 − 随机 @0.50** | **+0.4905** | [+0.3941, +0.5893] | 不含 0 |
| **压缩 @50% − 不压缩** | **−0.0011** | [−0.0803, +0.0771] | **含 0 → 持平** |
| **别名 − 删除** | **+0.0014** | [−0.0252, +0.0285] | **含 0 → 持平** |

三条读法：

1. **锚点增益在三个预算上都稳健**（+0.22 ~ +0.25，CI 全部不含 0）。这不是单预算的偶然。
2. **压缩 50% 与不压缩在统计上无法区分** —— "压缩是免费的"现在有区间支持，不只是点估计持平。
3. **别名与删除的效用差 +0.0014，CI 含 0，即统计上相等。** 这正是要点：**身份保全（collision 40 vs 0）是以零效用代价换来的**，不是拿分数买的。

### 8.3 增益跟着"案例类型"走，不跟着"数据集"走

按来源分组 bootstrap（锚点增益 @0.50）：

| 来源 | n | 锚点增益 | 95% CI |
|---|---:|---:|---|
| toolmem_raw | 20 | **+0.4487** | [+0.250, +0.650] |
| pec_home | 20 | +0.3503 | [+0.150, +0.550] |
| simuhome | 20 | +0.2505 | [+0.050, +0.450] |
| privacylens | 20 | +0.2410 | [+0.050, +0.440] |
| smartbench_tdcs | 20 | +0.0998 | [+0.000, +0.250] |
| **toolmem** | 12 | **+0.0119** | [+0.000, +0.036] |

`toolmem` 几乎零增益，而它恰好是**唯一一个 12 例全是 needle、0 个多实体案例的来源**（构建期记录：该来源的 tool 结果标量键逐条不同，无法构造"均匀属性"，因此不出 multi 案例）。

按案例类型直接切开，机制立刻显形：

| 案例类型 | n | 锚点臂 F1 | 纯冗余臂 F1 | 增益 | 95% CI |
|---|---:|---:|---:|---:|---|
| **multi_entity（多实体消歧）** | 40 | **0.5500** | **0.0000** | **+0.5489** | [+0.400, +0.700] |
| needle（单点取证） | 72 | 0.8117 | 0.7292 | +0.0821 | [+0.028, +0.150] |

**纯冗余度选择器在全部 40 个多实体案例上得分恰好为 0.0000 —— 不是偏低，是归零。** 一条锚点保护规则把它恢复到 0.5500。
在 needle 案例上它本来就能工作（0.7292），锚点规则只带来 +0.0821 的小幅提升。

**这条把机制与适用面同时钉住了**：增益的大小由"该案例是否需要区分多个同形实体"决定，而不是由数据集决定。聚合的 +0.249 正是 +0.549（40 例）与 +0.082（72 例）的加权混合。
