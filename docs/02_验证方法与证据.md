## 2. 核心指标定义

本次工作提出并使用了三个**跨度级**指标，用来在没有下游模型的情况下判断"合并在破坏什么"：

| 指标 | 定义 | 为什么用它 |
|---|---|---|
| `hit_answer` | 一个合并簇里，**既有**含答案跨度的单元、**又有**不含答案的单元 | 直接度量"合并是否把答案与噪声混在一起"→ 效用风险 |
| `mix_sens` | 一个合并簇里，既有命中敏感标识符的单元、又有不命中的 | 度量"敏感内容是否被混进普通内容"→ 隐私风险 |
| `fuse_2sec` | 一个合并簇里**融合了两个不同敏感标识符** | 最危险的失败模式：两个秘密混成一类后无法区分 |

**为什么这三个指标可信**：它们都只看"合并簇的组成"，不依赖任何模型判断，**完全确定性、可复现**。

## 3. 验证设计逐个说明

### 3.1 V2 系列：合并可行性（**先证明机制，再投入实现**）

**要回答的问题**：相似度合并会不会按构造破坏效用或隐私？

**设计**：
- 样本：7 个数据集抽 581 例（SmartBench TDCS / PEC-Home / toolmem / PrivacyLens / HotpotQA / SQuAD / SimuHome）
- 敏感项：每例注入 3 个合成标识符（email / phone / account），位置轮换
- 单元：句 / 行 / 200 字符窗
- 相似度：① 字符 3-gram TF-IDF 余弦（保守代理）；② **真语义嵌入**（llmlingua-2 的 XLM-R-large，mean-pool）
- 合并：**比例驱动的贪心配对**（不是阈值），合并到目标比例
- **对照**：`random_adjacent`（随机相邻配对）+ `random_far`（随机非相邻配对，间隔≥2）

**为什么"非相邻随机"这个对照重要**：敏感块是连续的，随机相邻配对会频繁跨越敏感块边界 —— 这可能是个伪影。加一个"非相邻"对照就能排除。

**结果**：mix_sens 相似度 **0.0–2.6%** vs 随机 **15.3–20.7%**（两种随机对照都一致）。

**证据**：`results/reports/v2c_report.txt`、`v2d_report.txt`、`results/cells/v2c_cells.json`

### 3.2 V3 系列：约束消融（**找出哪个约束才是功臣**）

**要回答的问题**：三个约束（重要性 / 隐私 / 距离有界）各值多少？

**设计**（作业数组 4 配置，每任务 1 卡）：

| 配置 | 注入形态 | 单元粒度 | 臂 |
|---|---|---|---|
| `scatter` | 分散式 | 句 | sim / cons / imp / cons_imp / random×2 |
| `guard` | 连续块 | 句 | sim / cons / imp / cons_imp / random |
| `gran` | 连续块 | **200 字符窗** | sim / imp / cons_imp / random |
| `bound` | 分散式 | 句 | sim / bound(τ=0.75,簇≤4) / rand4 |

**关键设计**：`cons_imp_emb` 把两个约束**同时**加上，可以直接看"两个目标能不能同时归零"。

**结果**：
- `imp_emb` → hit_answer **精确 0.0%**（6 个设置全部）
- `cons_imp_emb` → hit **0.0%** 且 mix **0.0%**，且**簇数与纯相似度完全相同**（不牺牲压缩率）
- `cons_emb ≡ sim_emb`（句子级）→ 隐私护栏冗余；**但 200 字符窗级必需**（见 `gran` 补跑）

**证据**：`results/reports/v3_*_report.txt`、`results/cells/v3_*_cells.json`

### 3.3 V1 系列：paraphrase 覆盖率（**量化导师点名的缺口**）

**要回答的问题**：正则去敏在改述/格式变化下还剩多少覆盖率？现有指标能不能看见这些泄漏？

**设计**：
- 全语料：**17,975 案例 / 53,925 个标识符**（项目已跑完的那批）
- 三个检查器对照：
  - **A. 原版 `exposure()`**：小写去非字母数字 + 子串匹配（项目现用）
  - **B. 变体枚举**：对每个 secret 生成 4–8 个改述/格式变体，任一命中即算检出
  - **C. 变体枚举 + 无序 token 集合**：再加"特征 token 全在但顺序/格式变了"的判定
- 同时测 `redact()` 的删除率

**结果**：
- 规范格式：原版检查器 **100%** 检出
- 脱敏后：原版检查器 **0.00%**（= 项目报告的 100% 移除）
- **脱敏后严格检查器仍检出 1.14%** ← 真实残留
- `blind_spot = 0.00%`（**因为语料只含规范格式**）

**⚠️ 这次验证产生了一个必须记录的修正**：
首次运行报 `redact_miss = 12.35%`，我做了**独立诊断**（作业 1444040），打印命中规则与上下文，证明是**我自己的启发式 bug**：数字段检查被错误应用到账号类型，hex marker 抽出的"数字段"退化成单字符（如 `"1"`、`"963"`）→ 乱匹配。`variant_substr` 与 `tokenset` 规则**一次都没命中**。限制为仅对 phone 后，真实值 **1.14%**。

**证据**：`results/reports/v1_report.txt`（bug 版）、`v1fix_report.txt`（修正版）、`v1b_report.txt`（诊断）、`results/logs/v1b-1444040.out`

### 3.4 E2E 系列：端到端 F1（**唯一能回答"能不能赢"的方法**）

**设计**（三次迭代，逐次修正）：

| 版本 | 案例 | 臂 | 关键设计 |
|---|---|---|---|
| v1 | 1000 | 5 | 随机抽样 → **数字作废**（金标准 bug） |
| v1b | 1000 | 5 | 修正金标准后重跑 |
| v2 | 1000 | 6 | **确定性哈希选案** + 存 `case_key` 供 join + 加 token 级臂 |
| v3 | 1000 | 4 | 直接读 **他们 DB 里存好的 `mask_quito_x` 输出** |

**共同控制**：同案例、同 50% token 预算、同模型（Qwen2.5-7B-Instruct）、同提示词、同官方 SQuAD 评分器。

**v2 的关键设计——逐例 join**：
- 我的结果存 `case_key`
- 直接查他们 `results.sqlite` 的 `metrics` 表（826,850 行），按 `case_key` + `method` + `rate` 取他们的逐例分数
- **这样比较的是同一批样本上的同一指标**，不是我跑一遍他们跑一遍的松散对比

**v3 的关键设计——读已发布输出**：
- 发现他们的 `jobs.payload` 里存了**每个 case 每种方法的完整压缩文本**（zlib 压缩的 JSON，含 `matched.text` / `native.text` / 所有 `trials`）
- 所以**不需要重实现 QUITO-X**，直接拿他们的输出当输入

**证据**：`results/reports/e2e*_report.txt`、`join_report.txt`、`results/percase/e2e2_percase.jsonl`

## 4. 验证的可靠性设计（为什么这些结论能信）

| 设计 | 作用 |
|---|---|
| **比例驱动合并**（而非阈值） | 阈值方案在 3-gram 余弦下根本不形成簇（首次尝试 tau=0.5 得 0 个簇）；比例驱动模拟真实压缩器的"按预算合并"语义 |
| **两个随机对照**（相邻 + 非相邻） | 排除"敏感块连续"造成的伪影 |
| **两种相似度度量**（字符 + 真嵌入） | 字符 n-gram 是保守代理，真嵌入是上界；两者结论一致才可信 |
| **两种注入形态**（连续块 + 分散式） | 排除"结论依赖注入方式" |
| **三个合并比例**（0.125 / 0.25 / 0.50） | 排除"只在某个压缩率下成立" |
| **四种粒度**（句 / 行 / token-16 窗 / 200 字符窗） | 排除"粒度决定结论" |
| **逐例 join 而非均值对比** | 排除样本不同导致的假差异 |
| **独立诊断异常值** | V1 的 12.35% 就是这样被查出是 bug 的 |
| **基线复现验证** | E2E v3 复现 `mask_quito_x` 到 ≤1 分误差，证明整条管线可信 |

## 5. 已知的验证局限（诚实标注）

| 局限 | 影响 |
|---|---|
| 敏感项是**合成标识符**，且**永远任务无关** | 无法测"敏感且任务相关"的冲突场景（= A5 的空白） |
| E2E 只在 **1000 例**上跑（500+500） | ±2–3pp 量级；+5~7pp 的效应超噪声，但更小的效应测不出 |
| E2E 用 **FP16 on V100**（基线原本 BF16 on 其他卡） | 已声明为数值偏离；但 `full` 臂复现到 89.53/55.30，与基线同量级 |
| **单模型**（Qwen2.5-7B） | 不能推广到其他模型 |
| `mask_quito_x` 的复现用的是**他们存储的输出**，不是我重跑 QUITO-X | 若他们的存储文本与当时评分所用文本不一致，会有偏差；但复现误差 ≤1 分，说明一致 |
| V3 的 4 个配置**不是同时**跑的（`gran` 是补跑） | 无影响（配置间独立） |
