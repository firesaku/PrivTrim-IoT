# 想法台账（Ideas Ledger）

> 本文档逐条记录本次工作中**提出过的每一个想法**，以及它的**验证状态**。
> 状态分四种：**✅ 已验证成立** / **❌ 已验证不成立** / **⚠️ 部分成立或依赖条件** / **⬜ 未验证**
> 每条都给出：提出依据 → 验证方式 → 结果 → 判定 → 证据文件。
>
> 时间范围：2026-10-15 ~ 2026-10-16

---

## 图例

| 符号 | 含义 | 判定标准 |
|---|---|---|
| ✅ | 已验证成立 | 有实测量化结果，方向明确，且有多设置一致 |
| ❌ | 已验证不成立 | 有实测量化结果，方向与预期相反或与对照无差别 |
| ⚠️ | 部分成立 / 依赖条件 | 在某些条件下成立、另一些不成立；或效应存在但不稳定 |
| ⬜ | 未验证 | 只有推理或引用，没有本次实测 |

## B 类：机制层想法（本次工作的主体）

| 编号 | 想法 | 提出依据 | 验证方式 | 结果 | 判定 |
|---|---|---|---|---|---|
| **B1** | **相似度聚类合并**能同时完成压缩与去敏 | PACT 的"距离有界聚类"思路迁移 | 7 数据集 581 例，3 个合并比例 × 2 个随机对照，字符 3-gram + 真语义嵌入 | `mix_sens`（敏感与非敏感混入同簇）：相似度 **0.0–2.6%** vs 随机 **15.3–20.7%** | **✅ 成立** |
| **B2** | **正则隐私前端几乎免费** | 项目既有 `mask_*` 32/32 全正 | ① 跨度级：16 对配对（V2）；② 端到端：3 次独立实验 | ① ΔF1 均值 **+3.25pp**（12/16 为正，最差 −0.23pp）；② 端到端 ≤0.4pp | **✅ 成立** |
| **B3** | 聚类合并**会吃掉答案跨度**（主要风险） | 文本 token 无视觉冗余，合并可能删掉判别信息 | 统计"合并簇是否同时含答案跨度与非答案内容"（hit_answer），与随机合并对照 | 相似度 **3.4–6.2%** vs 随机 **3.0–3.8%** → **无实质差别** | **❌ 风险不成立**（好消息） |
| **B4** | 相似度合并比随机合并**更安全** | 敏感内容内部同构、与正文不像 | 同上，看 `fuse_2sec`（两个秘密混成一簇） | 相似度 **0.0–0.2%** vs 随机相邻 **0.9–1.5%** | **✅ 成立** |
| **B5** | **重要性护栏**（`d_imp`：禁止答案与非答案合并）能消除效用损伤 | B3 显示有约 1/20 的合并混入非答案内容 | 加约束重跑，看 hit_answer | hit_answer → **精确 0.0%**，在 **2 种注入形态 × 3 个比例共 6 个设置全部为 0**；粒度换成 200 字符窗仍为 **0.0%** | **✅ 成立（本工作最干净的结论）** |
| **B6** | **隐私护栏**（`d_sens`）是必需的 | 直觉：应显式禁止敏感与非敏感合并 | 加约束 vs 不加，看 mix_sens / fuse_2sec | **粒度依赖**：句子级 `cons_emb ≡ sim_emb`（护栏一次未触发，冗余）；**200 字符窗级必需**（mix 0.0% vs 0.7–1.3%，fuse 0.0% vs 0.2–0.6%） | **⚠️ 部分成立** — 且**我中途推翻过自己一次**（先判冗余，补跑粒度后改判必需） |
| **B7** | PACT 原样的**距离有界聚类**能解决效用问题 | PACT 论文的做法 | 加 τ=0.75 相似度下界 + 簇大小 ≤4，看 hit_answer | mix_sens 0.0%，但 **hit_answer 仍是 5.1%**（比不加约束的 4.0% 还高） | **❌ 不成立**：距离有界只保隐私、不保效用 |
| **B8** | **token 级**会比句子级更好 | 项目数据里细粒度方法移除率更高 | 加 16-token 窗口臂，同案例同预算对比 | 句子级 F1 **50.81** vs token 级 **45.85**；SQuAD **60.63** vs **59.09** | **❌ 不成立**（token 重建碎片化伤流畅度） |
| **B9** | **粒度是主要瓶颈**（落后基线 27pp 的原因） | 差距大，先怀疑粒度 | E2E v2 逐例 join 基线 | 粒度不是主因；**主因是选择器**：`mask_quito_x` 保住 full 的 **98.2%**，我的最好臂只保住 **67.7%** | **❌ 不成立** |
| **B10** | 把聚类**叠到强选择器（QUITO-X）**上能提升 | 聚类在弱选择器上有 +7~8pp 增益 | 读他们 DB 里存好的 `mask_quito_x` 输出，叠聚类重跑（E2E v3） | SQuAD **−0.96pp**、HotpotQA **−6.03pp**，合计 **−3.50pp F1** | **❌ 不成立**（增益被强选择器吸收） |
| **B11** | 叠聚类能**省 token 而几乎不掉分** | 合并冗余应能腾出预算 | 同上，同时记录上下文 token 数 | 省 **15.4%** token（408.5→345.6）但掉 **3.5pp F1** | **❌ 不划算**（比例失衡） |
| **B12** | 聚类在**强选择器上也优于随机合并** | B4 在弱设置下成立 | 同 v3，`qtx_cluster` vs `qtx_random` | **不一致**：SQuAD **+5.43pp**（且 token 更少）✓；HotpotQA **−2.83pp** ✗；合计 +1.30pp | **⚠️ 部分成立，不稳定** |
| **B13** | 正则去敏**在改述上失效** | 导师点名要求覆盖 paraphrase | 生成 600 个改述/格式变体，跑现有 `redact()` | 完整值删除率 **100%（规范格式）→ 9.1%（变体）**；email 25%、**phone 0%、account 0%** | **✅ 成立**（缺口被量化） |
| **B14** | 现有隐私指标存在**看不见的泄漏盲区** | 由 B13 推断 | 全语料 17,975 案例 / 53,925 标识符跑原版 + 严格版检查器 | **修正**：全语料 `blind_spot = 0.00%`（因为语料只含规范格式）；**"40% 隐形"只成立于生成的改述变体上，是反事实推演** | **⚠️ 需严格区分**：语料本身无盲区；盲区在"若输入含改述"时才出现 |
| **B15** | 正则**漏删率 12.35%** | 首次全语料运行结果 | 抽样诊断（作业 1444040），打印命中规则与上下文 | **是我自己的 bug**：数字段检查被错误应用到账号类型，hex marker 抽出单字符（`"1"`、`"963"`）乱匹配；`variant_substr`/`tokenset` 一次未命中 | **❌ 我的错误** → 修正后 **1.14%** |
| **B16** | **证据闭包**（关联保留）能提升安全完成率 | 项目主假设 | 引用项目既有实验（本次未重跑） | 闭包 vs 简单元数据排序 **10+ 次复现全部打平**（8/8 vs 8/8 等） | **❌ 项目既有结论** |
| **B17** | **接口守卫**能提升安全性 | 直觉：出口加检查 | 引用项目既有实验 | direct 界面 61/64 → 加守卫 **64/64**（修 3 例）；但**加守卫后"更好接口"的收益变成恰好 +0.00pp** | **⚠️ 部分成立**：守卫会吸收接口增益 |
| **B18** | **目标接口修复**能大幅提升安全完成 | 项目既有方向 | 引用项目既有实验 | Qwen2.5-7B：47/64 vs 24/64；配对 **+31.25pp [+18.75, +43.75]**（CI 不含 0） | **✅ 项目既有结论**（能力线唯一强正机制） |
