## 23.1 硬件与调度

| 项 | 要求 |
|---|---|
| 加速卡 | **1 × NVIDIA H200（141 GB）** 或同级别（A100 80GB 亦可跑，批次需减小） |
| CPU 任务 | 用于外部方法压缩与 Perception Compressor（每节点 24 核、64 GB 内存足够） |
| 调度器 | **Slurm**（所有脚本使用 `#SBATCH` 指令） |
| 分区 | 需自备一个 GPU 分区（脚本中以 `gpu` 表示）与一个 CPU 分区（以 `prod` 表示） |

提交前**必须自行替换**脚本里的两处占位：

```bash
#SBATCH --account=<SLURM_ACCOUNT>          # 改成你自己的账号
RD=/path/to/project                        # 改成你自己的项目路径
```

## 23.5 预算与臂

```text
预算点    : 0.25 / 0.50 / 0.75（主实验）
            0.05 / 0.10 / 0.15 / 0.20（预算曲线）
外部方法  : 统一压到 50%（原码固定 n//2），主对比锚定 OURS@0.50
```

21 条内部臂（见 `code/longctx/e2e_longctx_r5full.py` 的 `ARMS`）：

```
full, delete, alias                       （整段处理，无预算）
budget_cluster / budget_cluster_link      （原文 + 冗余删 / +锚点保护）
budget_random                             （随机删，下界）
delete_budget, alias_budget, alias_budget_link
```

## 23.6 关键运行开关

| 开关 | 作用 | 默认建议 |
|---|---|---|
| `PT_ALIAS_KEY` | 打乱别名字母分配顺序，**消除秩泄漏** | **必须设置**（否则攻击者可 100% 逆推别名） |
| `--alias-question` | 问题中的实体同步替换为别名 | 开启（消融显示 +0.2053） |
| `--ext-arms` | 外部方法压缩产物清单 | 见 `code/build_ext_arms.py` |

> ⚠️ 未设 `PT_ALIAS_KEY` 时别名按值升序发放，攻击者已知值集合即可完全逆推。
> 该问题与修复见 `docs/21` 第 21.1 节。

## 23.7 脚本的 Slurm 守卫（重要）

`code/` 与 `code/longctx/` 下的**重脚本**（会加载模型或批量处理）顶部都有一段守卫：

```python
if not os.environ.get("SLURM_JOB_ID"):
    ... exit(97)
```

行为：**检测不到 `SLURM_JOB_ID` 就拒绝运行**（退出码 97）。
目的是防止在共享登录节点上误跑重计算（事故背景见 `docs/22`）。

- 在 Slurm 作业中运行：自动通过（`SLURM_JOB_ID` 由调度器设置）
- 本地想试跑（例如 `--help` 或小样本）：显式设置一个假值即可

```bash
SLURM_JOB_ID=local python code/run_pc.py --help
```

纯分析脚本（`analyze_*.py`、`build_*.py`、`make_*.py`）**没有**守卫，可随意本地运行。

## 23.8 复现主表的步骤

```bash
# 1) 解压数据
gunzip -k data/longctx_max.jsonl.gz

# 2) 全量主实验（21 臂，32 分片，启用别名秩泄漏修复）
export PT_ALIAS_KEY='<your-key>'
sbatch code/hpc_scripts/slurm_20261027/keyfull.slurm

# 3) 外部基线压缩（5 个方法，各 32 分片）
sbatch code/hpc_scripts/slurm_20261027/extcomp.slurm
sbatch code/hpc_scripts/slurm_20261027/extnew.slurm

# 4) 外部基线评测
sbatch code/hpc_scripts/slurm_20261027/extevalfull.slurm

# 5) 汇总（本地即可，无需 GPU）
python code/analyze_keyfull.py
python code/analyze_ext.py
```

预算曲线：`sweep.slurm`；跨模型：`xmistral.slurm`；公开基准：`pubcomp.slurm` + `pubeval.slurm`。

## 23.9 已知偏差（复现时须知晓）

1. 运行**非逐位可复现**：同臂两次运行 F1 差约 0.0006（fp16 算子非确定性），
   小于 0.001 的差异不作方法解释
2. `batch=8` 比 `batch=2` 慢约 25%，且 4/1806 条预测不同，故主实验用 `batch=2`
3. DAC 基线在长上下文上大量 OOM，仅覆盖 300/2728 例，不可与全量并列
4. Perception Compressor 的 guiding questions 由 Qwen2.5-7B 生成（原作者未发布生成脚本）
